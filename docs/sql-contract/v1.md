# Bookclerk SQL contract v1

This document is the **normative** definition of `sqlContractVersion = 1`.
BookclerkSQL is a **host-owned portable subset**, not “SQLite everywhere.”
Adapter admission is “passes Bookclerk SQL v1 conformance,” not “looks like
SQLite or PostgreSQL.” Guests speak only this grammar. Adapters alone lower
to SQLite, PostgreSQL 16+, or Cloudflare D1. Machine-readable vectors live under
[`crates/bookclerk-db-exec/testdata/sql_v1/`](../../crates/bookclerk-db-exec/testdata/sql_v1/)
and are consumed by `bookclerk-db-exec` lowering tests and library conformance.

## Version compatibility

- Contract versions are **monotonic supersets**: every statement form, type,
  and semantic guarantee in version *N* remains valid in version *N+1*.
- Guests advertise the highest version they implement as `sqlContractVersion`.
- Hosts require `sqlContractVersion >= SQL_CONTRACT_VERSION` (currently `1`).
- A **non-superset** redesign needs a new contract identity and a plugin ABI
  break (`apiVersion` / `plugin.toml` `api_version`). Do not increment this
  scalar and keep `>=` if N+1 would drop or change a guarantee of N.

## Grammar (canonical form)

Guest SQL is admitted in this order:

1. **SQL-v1 grammar** — positive/versioned Bookclerk SQL (not a SQLite dialect).
2. **Typed expressions** — the host builds exactly one resolved typed proof
   (`ResolvedStatement`) per canonical statement, bound to the SHA-256 of that
   exact SQL string (after host semantic desugars). Authorization, schema
   companions, result expectations, and adapter lowering consume that proof;
   none re-resolve names or types. Proofs travel on host→adapter
   `AdapterDatabaseSession.execute` (`AdapterExecuteRequest.proofs`).
   `GuestDatabase.execute` stays untrusted `ExecuteRequest` without proofs.
   The proof is typed against a durable binding catalog (`bookclerk_sql_catalog` /
   `bookclerk_sql_schema`) plus in-request `CREATE`/`DROP`. Unknown
   tables/columns fail closed. Empty catalog means “no plugin tables,” not
   “unknown → NULL.” `host_authoritative` skips **authorization** only;
   typing and TEXT lowering still run (from the canonical host schema or an
   equivalent already-resolved proof). New atomic batches snapshot catalog
   and physical types in autocommit **before** `BEGIN`, so SQLite does not
   hold a reserved lock across paged catalog loads. Nested typed `execute` on
   an already-open transaction still snapshots inside that transaction.
   `SchemaAction::Create` stores the full `CreateTableSchema` (ordered columns,
   SQL-v1 types, nullability, identity, PK/UNIQUE/defaults/CHECK/FKs) plus
   fingerprint and no-op. Catalog companions and Postgres identity objects
   consume that schema; they do not reparse canonical CREATE text. Host
   catalog INSERT/DELETE DML is built with SeaQuery (`SqliteQueryBuilder`)
   from the proof. Adapter-private catalogs are reserved names; guests cannot
   grant themselves `sqlite_master` / `information_schema` probes.
3. **Binding scope/security** — isolated schema, reserved-name, and ref checks
   using `proof.physical_accesses` and `proof.functions` (no second alias walk)
   when a type environment is present (binding-owned and library guests with
   catalog types). A projection wildcard (`SELECT *`, `alias.*`, `RETURNING *`)
   records each physical column plus `"*"` on that table; column-scoped grants
   reject the wildcard the same way the lexical authorizer does. `column: None`
   is table presence only (FROM / DML destination), not a star. Library guests
   without a type env still use lexical `parse_guest_sql_refs` so SQLite-only
   helpers remain authorizable without pretending they are portable SQL-v1 types.
4. **Capability/limit validation** — binds, result selection, negotiated caps.
5. **Canonical `ExecuteRequest`** — host wrap (receipts) without engine identity.
   Receipt wrappers get their own proofs bound to the wrapper SQL.
6. **Adapter-edge lowering** — at execute, against the isolated physical DB,
   reading TEXT collation sites from the proof (never `ident_is_text`).

Hosts emit **canonical Bookclerk SQL**. Host semantic desugars (not adapter
rewrites) make unspecified `ORDER BY` explicit (`NULLS FIRST`/`LAST`, SQLite
default) and wrap `/` `%` divisors as `NULLIF(x, 0)`. Adapters lower to the
engine at execute time. Domain planners must not branch on engine identity.

- **DML and queries** — `bookclerk-db-exec::lower_canonical_sql_typed`
  (placeholders, `IFNULL`, `json_extract`, `INSERT OR IGNORE`, 2+-arg
  `min`/`max`, `json_valid`, `round`/`sum`/`avg` wire types, `LIKE`→`GLOB`,
  proof-directed `COLLATE "C"` and INTEGER overflow). Default NULLS are
  **not** adapter rewrites.
- **DDL types and identity** — adapter execution edge
  (`realize_host_ddl` / binding DDL helpers).
  The generic DML pass does not classify statements as DDL.
- **`INSERT OR IGNORE … SELECT` / `WITH`** — adapters wrap the row source as
  `SELECT * FROM (<source>) AS _bc_src WHERE true` before `ON CONFLICT DO
  NOTHING` so SQLite/D1 UPSERT is unambiguous. `VALUES` is not wrapped.
  `_bc_src` is reserved (same class as catalog names).

### Placeholders

- Positional binds use bare `?` only (1-based order of appearance in code spans).
- `$n`, `?NNN`, and other engine-specific bind spellings are outside SQL v1
  and are rejected for every guest before adapter dispatch.
- Placeholders inside string/identifier literals, line/block comments, and
  PostgreSQL dollar-quotes are not binds (adapters must preserve them).

### Statement forms

Supported top-level forms for guest-authorized and host-authored plans
(fail-closed recursive-descent grammar, not a denylist):

| Form | Notes |
| --- | --- |
| `WITH` CTEs + `SELECT …` | CTE bodies are `SELECT` only (no nested DML). `DISTINCT` is admitted; `DISTINCT ON` is not. Mixed aggregate + non-aggregate select lists are SQLite-shaped and **not** in this contract; keep aggregates in their own statement (or `GROUP BY`). |
| `SELECT` clauses | `FROM` / `JOIN` (`INNER` / `LEFT` / `CROSS`; not `RIGHT` / `FULL`), `WHERE` / `GROUP BY` / `HAVING` / `ORDER BY` [`ASC`\|`DESC`] [`NULLS FIRST`\|`LAST`] / `LIMIT` / `OFFSET`, `UNION [ALL]` (not `EXCEPT` / `INTERSECT`). |
| `INSERT INTO …` / `INSERT OR IGNORE INTO …` | Optional `RETURNING` |
| `UPDATE …` / `DELETE …` | Optional `RETURNING` |
| Schema DDL | Host-only for library and session guests. `GuestSqlPolicy::binding_owned` admits idempotent `CREATE`/`DROP` `TABLE`/`INDEX` `IF [NOT] EXISTS` on a physically separate plugin database. Binding helpers are this contract (not a wider SQLite dialect). Postgres adapters lower canonical types (`INTEGER PRIMARY KEY AUTOINCREMENT` → `BIGINT PRIMARY KEY` plus a transactional identity trigger, `BLOB` → `BYTEA`, case-insensitive) at their execute edge. |

Expression operators (closed): `=` `<>` `!=` `<` `>` `<=` `>=`, `AND` `OR` `NOT`,
`IS [NOT] NULL`, `IN`, `BETWEEN`, `LIKE` (not `ILIKE`), `\|\|` `+` `-` `*` `/` `%`,
`CASE`, `CAST(x AS INTEGER\|REAL\|TEXT\|BLOB\|BOOLEAN)`, policy-allowed function
calls, `.` qualification, `?`, literals. Rejected for every guest: `::`,
`ILIKE`, `SIMILAR`, `OVER`, `FILTER`, `GLOB` / `MATCH` / `REGEXP` / `COLLATE`.

`INSERT OR IGNORE` is canonical and means **unique / primary-key conflict
only**. `NOT NULL` and `CHECK` still abort on every backend. Adapters lower
the form to `INSERT … ON CONFLICT DO NOTHING` (conflict clause before
`RETURNING`) for SQLite, D1, and Postgres — SQLite `OR IGNORE` would otherwise
swallow `NOT NULL`. When the source is `SELECT`/`WITH`, the wrap above is
required. `REPLACE INTO`, `INSERT OR REPLACE` / `OR ABORT` /
`OR FAIL` / `OR ROLLBACK` are outside SQL v1 and are rejected before adapter
dispatch.

Binding `CREATE TABLE` / `CREATE INDEX` types are `INTEGER`, `REAL`, `TEXT`,
`BLOB`, and `BOOLEAN` only. `AUTOINCREMENT` is valid **once**, immediately
after `PRIMARY KEY`, and only when the column type is `INTEGER` (`INTEGER
PRIMARY KEY AUTOINCREMENT`). `INTEGER AUTOINCREMENT`, `REAL AUTOINCREMENT`,
and duplicate `AUTOINCREMENT` are rejected. `BOOL` is not an alias. Tails
such as `STRICT`, `WITHOUT ROWID`, `JSONB`, `NUMERIC(p,s)`, `VARCHAR(n)`,
`CASCADE` / `RESTRICT` on `DROP`, and backend-specific index clauses
(`USING`, `INCLUDE`, column `COLLATE`) are rejected. Adapter lowering of
type/identity tokens and `RETURNING` is case-insensitive in code spans (the
host write-gate constant is still matched exactly).

Identity after `INTEGER PRIMARY KEY AUTOINCREMENT` is SQLite-equivalent:
after an explicit id insert, the next omit-id is `max(committed id)+1` and
deleted ids are not reused. Explicit identity values are admitted. Postgres
adapters do **not** use `BIGSERIAL`/`setval` (those do not roll back with the
`ExecuteRequest`). They keep a transactional `BIGINT` high-water row in
adapter-private `bookclerk_identity` and a `BEFORE INSERT` trigger generated
from the **parsed** identity column name. `DROP TABLE` deletes that table's
catalog and identity rows in the same atomic request and drops
`bc_if_<digest>()`; it does **not** emit `DROP TRIGGER … ON` after the
relation is gone. Recreate starts at 1.
SQLite/D1 keep native `AUTOINCREMENT`. Guests cannot name `bookclerk_identity`
or `bookclerk_sql_catalog`.

### Identifiers and quoting

- Identifiers are canonical **unquoted** names: `[A-Za-z_][A-Za-z0-9_]*`,
  **≤ 63 bytes after case fold** (PostgreSQL `NAMEDATALEN-1`). 63 accepted;
  64 rejected. Quoted / mixed-case object names (`"Foo"`, `` `Foo` ``, `[Foo]`)
  are rejected. Adapter-private Postgres identity objects use hash-based names
  with separate prefixes: `bc_if_<digest>` (function) and `bc_it_<digest>`
  (trigger), 16 hex digits of SHA-256 of the folded table name, always under
  63 bytes. Two canonical names that would collide under Postgres 63-byte
  truncation produce distinct generated object names.
- Unquoted names fold to lowercase in authorization (`guest_sql`); adapters
  must not reinterpret authorization. `CREATE TABLE Foo` and `SELECT … FROM
  foo` name the same object on every admitted backend.

## Types and `DbValue`

| Wire (`DbValue`) | Canonical SQL expectation |
| --- | --- |
| `null(expectedType)` | SQL `NULL` with typed metadata |
| `bool` | Canonical SQL `BOOLEAN` (not INTEGER 0/1 storage leaking onto the wire) |
| `int64` | Exact 64-bit integer (not JSON number) |
| `float64` | IEEE float |
| `text` | UTF-8 text: Unicode scalar values excluding U+0000 |
| `bytes` | Opaque byte string (NULs allowed) |

Unknown Cap'n union members fail closed as `unsupported`.

### Portable TEXT

BookclerkSQL `TEXT` is Unicode scalar values on the UTF-8 wire, excluding
U+0000. UTF-8 is the encoding, not a smaller repertoire. The host rejects NUL
in parser literals, `DbValue::Text` binds/results, and catalog TEXT cells
**before** adapter dispatch, including SQLite. `BYTES`/`BLOB` may contain
`0x00`. PostgreSQL adapters require `server_encoding` / `client_encoding`
UTF8 (or a strict UTF-8 equivalent) at connect; SQL_ASCII / LATINn fail
closed.

### Advertised numeric limits

Host admission enforces advertised `DbCapabilities` before dispatch. Adapters
must not over-advertise a physical engine limit they cannot hide.

| Field | Meaning |
| --- | --- |
| `maxBinds` / `maxStatements` / `maxPayloadBytes` | Binds, statements, and canonical SQL+binds per statement |
| `maxResultRows` / `maxResultBytes` / `maxCellBytes` | Result envelope (fail closed, never truncate) |
| `maxRequestBytes` / `maxAtomicResultBytes` | Whole encoded request / reply |
| `maxFunctionArgs` | Physical vararg ceiling after adapter hiding |
| `maxSchemaColumns` | Columns per `CREATE TABLE` / result width |
| `maxPatternBytes` | UTF-8 bytes of a `LIKE` pattern value (literals and TEXT binds). Sqlite-family GLOB expansion is 3× for `[` `*` `?`; D1 advertises 16 so expanded GLOB stays ≤ 50 |

`json_object` even arity 2–32 is portable (16 key/value pairs). That matches
D1’s physical `maxFunctionArgs`. Sqlite-family adapters must not nest
`json_patch` to admit more pairs: JSON Merge Patch deletes null values and
changes duplicate-key behavior. Scalar `min`/`max` / `coalesce` are already
≤ 32 in the helper table. Postgres `json_build_object` does not need nesting
and is cast to TEXT (`(json_build_object(…)::text)`) except when a nested
`json_object` is a constructor value (that call stays `json` so it nests as
an object). Unproven `LIKE` pattern expressions fail closed when `maxPatternBytes` is
finite. Do not use `PRAGMA case_sensitive_like`.

### NULL and coercion

- Typed null carries `expectedType` for empty-result metadata and decode.
- Adapters must not collapse distinct Cap'n types through JSON number/array
  shims on the granted Cap'n path.
- **`CAST` matrix (proven only):** same-type `CAST`; `INTEGER` ↔ `REAL` when
  the conversion is proven; typed `NULL` to any admitted type. Rejected:
  `TEXT`→`INTEGER`/`BOOLEAN`/`BLOB` (including `CAST('1' AS INTEGER)`),
  `BLOB`→`TEXT`/`INTEGER`, `BOOLEAN`↔numeric, and any untested coercion.
  Store the value in the destination type instead.
- Unification (same rules on every backend): `IFNULL`/`COALESCE`/`NULLIF`/
  `CASE`/`UNION` arms, comparisons, scalar `min`/`max`, arithmetic
  (`INTEGER+REAL` → `REAL`). `sum(x)` requires `INTEGER`. `avg`/`round`
  require numeric. `lower`/`upper`/`LIKE` require `TEXT`.
- **BOOLEAN contexts** (`BOOLEAN | NULL` only): `WHERE` / `HAVING` /
  `JOIN … ON` / `DELETE`/`UPDATE` WHERE, searched `CASE WHEN <pred>`,
  `NOT` / `AND` / `OR` operands, and `CHECK (…)` on binding `CREATE TABLE`.
  `SELECT 1 WHERE 1` is rejected. Simple `CASE expr WHEN v` unifies `v` with
  `expr`.
- **Assignment sites:** `INSERT` destination list is the explicit column list
  or catalog declaration order. `VALUES` **and** `SELECT`/`WITH` must match
  arity and unify with each dest column. `UPDATE … SET col = rhs` uses the
  same dest-typing rule. Guest v1 does not admit `ON CONFLICT … DO UPDATE SET`
  (canonical form is `INSERT OR IGNORE` → adapter `ON CONFLICT DO NOTHING`).
- **Operators:** `+` `-` `*` `/` are INTEGER/REAL/NULL (result REAL if any
  REAL). `%` is INTEGER/NULL only (REAL is not portable). `||` / `LIKE` are
  TEXT/NULL. Comparisons unify both sides.
- **Helpers (typed arguments):** `replace(TEXT, TEXT, TEXT) → TEXT`;
  `substr(TEXT, INTEGER [, INTEGER]) → TEXT`; `round(numeric [, INTEGER]) →
  REAL`; `lower`/`upper`/`trim` TEXT-ish; `length` TEXT|BLOB; `json_extract`
  TEXT path; `sum` INTEGER-only. Unknown helper names are grammar-denied;
  typecheck does not `Ok(NULL)` for unknown calls.
- **Derived names / CTEs:** visible FROM keys are `AS alias` (or the table
  name). `WITH c(x, y) AS (…)` honors explicit CTE output names. Recursive
  CTEs infer the **anchor** first, publish those concrete types into
  self-scope, then typecheck recursive arms and unify every arm with the
  anchor. Anonymous or duplicate derived columns are rejected when they must
  be addressable (`SELECT 1` in a CTE later qualified, `AS (a, a)`,
  expression columns without `AS`). Top-level `SELECT` lists may omit `AS`
  (cells are positional). Postgres labels those items `?column?`; the
  adapter uniquifies colliding labels. Explicit duplicate aliases (`SELECT x, x`)
  still fail closed. Correlated subqueries resolve qualified
  aliases against enclosing FROM maps (nested `EXISTS` may name `i.user_id`
  after `FROM portal_identities i`).
- **Schema fingerprint:** `CREATE TABLE IF NOT EXISTS` is keyed on a
  structured schema IR (column order/names/types, identity, DEFAULTs, and
  admitted constraints — not normalized CREATE text). Catalog has the table
  and the fingerprint matches → no-op (no catalog/identity companions).
  Fingerprint differs → reject. Catalog lacks the table → INSERT catalog/
  schema rows (no `ON CONFLICT DO UPDATE`); identity companions only on this
  path. Physical reconciliation on SQLite, D1, and PostgreSQL fail-closes:
  catalog absent + physical exists (do not adopt orphans), catalog present +
  physical missing, or catalog vs physical column IR disagree. D1 uses the
  same `sqlite_master` fingerprint path as SQLite. Catalog load is fail-closed
  (`Result`): RPC/adapter/shape errors are `Err`; missing catalog objects are
  `Ok(empty)`. Rows page by keyset `(table_name, ordinal)` at
  `min(negotiated maxResultRows, FIRST_PARTY_MAX_RESULT_ROWS)` with the
  binding cancel and deadline forwarded. Malformed cells / unknown `sql_type`
  fail closed.
- **Runtime semantics (portable):** `/` and `%` by zero yield NULL. The host
  rewrites the divisor as `NULLIF(x, 0)` unless it is already structurally
  `NULLIF(<expression>, 0)`. A `NULLIF` whose second argument is not `0`
  (for example `NULLIF(0, 1)`, which evaluates to `0`) still gets an outer
  guard. Adapters must not repeat this rewrite. INTEGER `+` `-` `*` and `abs` in
  DML/query SQL that would overflow i64 yield NULL (proof-directed `CASE`
  wraps; guests must not depend on wraparound or a backend error). Overflow
  wrapping is **not** applied to `CREATE TABLE` `CHECK` expressions; INTEGER
  `+` `-` `*` `abs` in `CHECK` is rejected at admission. `round` halfway rounds
  away from zero (`round(1.5)=2`, `round(2.5)=3`) via Postgres `NUMERIC`.
  `substr` is 1-based; portable vectors use start ≥ 1 and length ≥ 0.
  Negative/`NULL` `substr` indexes are outside the portable claim. `length` of
  TEXT is characters; `replace` / `lower` / `abs` of values in range follow
  engine defaults locked by shared vectors.
  Host dispatch-latency SQL may call `julianday(TEXT) → REAL`; Postgres
  lowering rewrites that exact expression to `EXTRACT(EPOCH …)`. Guests
  cannot call `julianday` (not in the binding helper allowlist).
- **`DEFAULT`** must match the declared column type: integer literals for
  `INTEGER`, numeric for `REAL`, strings for `TEXT`, `X'hex'` for `BLOB`
  (kept in v1; Postgres DDL lowering rewrites `DEFAULT X'deadbeef'` to
  `DEFAULT decode('deadbeef', 'hex')` after `BLOB`→`BYTEA`), `TRUE`/`FALSE`
  for `BOOLEAN` (not `1`). Parenthesized `DEFAULT (…)` is rejected unless the
  inner expression is a matrix-legal `CAST`.
- Admitted helper signatures already land in the universal `DbValue` domain
  (`round` → `Float64`, integer `sum`/`count` → `Int64`, `avg` → `Float64`);
  callers are not required to `CAST` for those shapes. Other computed numerics
  that would be engine `NUMERIC` should still `CAST` to `INTEGER` or `REAL`.
- Conformance vectors compare **typed** `DbValue` cells (`Int64` is not
  `Float64(n)` or `Text("n")`). SQLite expression columns may still be
  `DbType::Unspecified`; Postgres OID mapping should be `Int64` / `Text`.

## Helpers (canonical)

| Canonical | Arity | Wire | Meaning |
| --- | --- | --- | --- |
| `IFNULL(a, b)` | 2 | (inputs) | First non-null |
| `json_extract(col, '$.path')` | 2 | text | JSON path extract |
| `json_object(k, v, …)` | even 2–32 | text | Object constructor (key/value pairs). Portable maximum is 16 pairs (32 arguments), matching D1 `maxFunctionArgs`. Adapters must not emulate larger calls with `json_patch`. |
| `json_valid(expr)` | 1 | int64 0/1 | Predicate (`= 0` / `= 1`) |
| `min(a, b, …)` / `max(a, b, …)` | 2+ | (inputs) | Scalar least/greatest. Any NULL argument yields NULL (NULL-poison). One-arg `MIN`/`MAX` stay aggregates. |
| `round(x)` / `round(x, n)` | 1–2 | float64 | Round; Postgres `CAST`s through `NUMERIC` onto `DOUBLE PRECISION`. |
| `avg(x)` | 1 | float64 | Average |
| `sum(x)` | 1 | int64 | Integer aggregate (REAL-sum portability is not claimed) |
| `count(*)` / `count(x)` | 1 | int64 | Count |

Wrong arity is rejected before dispatch, including `IFNULL`/`COALESCE`/`NULLIF`
(`2` / `2+` / `2`), `abs`/`sum`/`avg`/`count`/`length`/`lower`/`upper`/`json_valid`
(`1`), and even-arity `json_object` (`2`–`32` arguments, 16 key/value pairs). Postgres lowering
maps `IFNULL` / `json_*` / 2+-arg `min`/`max` to `COALESCE`, `jsonb` operators,
`(json_build_object(…)::text)` (nested `json_object` values stay `json` so they
nest as objects), `IS [NOT] JSON`, and `LEAST`/`GREATEST` with an explicit
NULL guard (`CASE WHEN a IS NULL OR b IS NULL … THEN NULL ELSE LEAST/GREATEST(…)
END`). SQLite/D1 execute those canonical forms directly after the unique-conflict
`INSERT OR IGNORE` rewrite. `MAX(attempt_count, 1)` in host plans is the same
2-arg scalar form.

Plugin-owned database bindings (`GuestSqlPolicy::binding_owned`) authorize
these helpers plus portable scalars (`abs`, `cast`, `coalesce`,
`length`, `lower`, `nullif`, `replace`, `substr`,
`trim`, `upper`). `hex` is not portable (PostgreSQL has no `hex()`); it remains
available to library guests. SQLite-only names (`strftime`, `typeof`, `group_concat`,
`iif`, `instr`, `quote`, `total`, `date`, `datetime`, `time`, `json_array`)
are denied so a binding cannot depend on a dialect the contract does not
guarantee. See [`docs/plugins.md`](../plugins.md#isolated-plugin-database-bindings).

### `ORDER BY`

Default NULL ordering matches SQLite: NULL sorts as **smallest** (`ASC NULLS
FIRST`, `DESC NULLS LAST`). The host desugars omitted NULLS into explicit
clauses before typecheck. Explicit `NULLS FIRST` / `NULLS LAST` is admitted
and left unchanged. Adapters must not repeat this rewrite.

TEXT `ORDER BY` is binary / code-point order. Postgres lowering applies
`COLLATE "C"` only at TEXT expression spans recorded on the statement proof
(comparisons, scalar `min`/`max`, `ORDER BY` keys, `LIKE` / `NOT LIKE`,
`lower`/`upper`). INTEGER/REAL/BOOLEAN/BLOB expressions never receive
`COLLATE "C"`. `json_extract` path string arguments are omitted from the
proof (so the path stays a bare literal for helper lowering); a comparison
or `ORDER BY` on a `'$.…'` string still receives `"C"`. Host-authored
`ORDER BY` TEXT uses the same annotations. SQLite/D1 need no COLLATE rewrite
(BINARY default).
The conformance suite uses ASCII and non-ASCII vectors. Locale-sensitive
Unicode order is outside v1.

Canonical `LIKE` is **case-sensitive**. Grammar keeps `LIKE` and still
rejects `ILIKE` and `ESCAPE`. SQLite/D1 adapters rewrite `LIKE`/`NOT LIKE` to
`GLOB` with bind-safe `replace` (escape `[` `*` `?`, then `%`→`*` `_`→`?`).
Do not use `PRAGMA case_sensitive_like`. Guests cannot write `GLOB`.

## Result semantics

- **`rowsAffected`**: mandatory (`affectedRows` capability). Reports rows
  changed by DML; `INSERT OR IGNORE` / `ON CONFLICT DO NOTHING` that insert
  zero report `0`.
- **`RETURNING`**: mandatory (`returning` capability). Column order and names
  come from engine metadata; empty results still expose column metadata.
- **Transactions**: one `ExecuteRequest` is one atomic batch. Failure before
  commit rolls back all statements in the request.
- **Errors**: stable categories (`conflict`, `deadline`, `invalidParams`,
  `internal`, …). Ambiguous commit / lost response uses durable receipt replay
  of the original `ExecuteReply`.
- **Bounds**: `maxResultRows`, `maxResultBytes`, `maxAtomicResultBytes`,
  `maxRequestBytes` fail closed before commit / dispatch. `maxLoweredStatementBytes`
  (`0` unspecified) is compared to a proof-aware sqlite-family lowering upper
  bound after `ResolvedStatement` exists. D1 advertises `100000` for that
  ceiling; `maxPayloadBytes` remains a proven canonical cap so mechanical-only
  lowering of an admitted statement stays within 100 KiB.

## Conformance admission

A new SQL adapter is admitted when it:

1. Negotiates `DbCapabilities` with `sqlContractVersion >= 1` and required
   semantic flags/limits (not by matching a plugin id or diagnostic `engine`).
2. Executes the **sql_v1** corpus (lowering + shared behavioral vectors) without
   host library changes keyed on adapter identity.
3. Keeps `sqlFamily` / `dialect` on `DbBootstrap` (host-private bootstrap
   metadata) only — not on typed `DbCapabilities`. `DbCapabilities` `@17` is
   `pluginDatabases`, `@18`–`@20` are numeric caps, `@21` is
   `maxLoweredStatementBytes`, and `@22`/`@23` are `consistentBackupRead` /
   `atomicUnitRestore`. Reports any diagnostic `engine` string on `DbBootstrap`;
   the host always emits canonical `?` SQL. Architecture lint forbids planner
   reads of bootstrap fields and host calls to physical lowering helpers.
